# Математика, 7 класс — интерактивный тренажёр

Тренажёр для повторения курса алгебры и геометрии 7 класса. Статический сайт на Vanilla JS/HTML/CSS, порт эталонного проекта [math6-trenazhor](https://github.com/BaikovaAlina/math6-trenazhor): визуальный стиль, страницы, навигация, проверка ответов, localStorage и формат Telegram-отчёта перенесены; содержимое заменено материалами 7 класса.

## Состав курса

- **Алгебра (102 ч/год):** рациональные числа и проценты; степени; одночлены и многочлены; формулы сокращённого умножения; разложение на множители; линейные уравнения и текстовые задачи; функции и графики; системы уравнений.
- **Геометрия (68 ч/год):** прямые, отрезки и углы; признаки равенства треугольников; равнобедренный треугольник; параллельные прямые; сумма углов и неравенство треугольника; прямоугольный треугольник; окружность и геометрические места точек.
- **Итог:** урок повторения и задания в стиле ВПР.

В `tasks.js` 48 вариантов (К-1…К-24 и Д-1…Д-24), всего **398 полей заданий** с ответами. Для каждого урока есть классная и домашняя работа. Памятки и разобранные примеры — в `theory.js`.

## Локальный запуск и проверка

Откройте `index.html` в браузере либо опубликуйте проект как GitHub Pages. Сборщик не нужен. Ответы проверяются немедленно: зелёная/красная обратная связь, допуск для чисел, десятичная запятая и дроби; подсказки и правила доступны в памятках. Имя и статистика сохраняются в localStorage: счётчики попыток/верных/ошибок ведутся суммарно и отдельно по уроку; на экране итогов есть сброс статистики.

## Публикация GitHub Pages

1. Создайте новый публичный репозиторий и загрузите файлы в корень ветки `main`.
2. В **Settings → Pages → Build and deployment** выберите **Source: GitHub Actions**.
3. Workflow `Deploy to GitHub Pages` отправляет в сайт только **публичный URL relay** из GitHub Actions Variable `TELEGRAM_RELAY_URL`. Значение Bot Token и Chat ID не внедряются в frontend.
4. После успешного workflow сайт будет доступен по адресу `https://<username>.github.io/<repository>/`.

## Telegram без публикации токена

Токен Telegram-бота нельзя хранить в публичном клиентском JavaScript. Клиент обращается к Cloudflare Worker, а Worker отправляет `sendMessage` в Telegram. Токен бота и фиксированный Chat ID хранятся только в Cloudflare Worker Secrets; GitHub Pages их не получает. Cloudflare Workers имеет бесплатный тариф, но перед использованием следует сверить действующие лимиты своего аккаунта.

### Однократная настройка Cloudflare Worker

1. Войдите в Cloudflare и создайте API Token с правом **Account → Workers Scripts → Edit**. Скопируйте Account ID из панели Cloudflare.
2. В GitHub откройте **Settings → Secrets and variables → Actions** и создайте Secrets:
   - `CLOUDFLARE_API_TOKEN` — токен Cloudflare;
   - `CLOUDFLARE_ACCOUNT_ID` — Account ID;
   - `TELEGRAM_BOT_TOKEN` — токен бота, перевыпущенный через `@BotFather`;
   - `TELEGRAM_CHAT_ID` — Chat ID учителя, которому бот присылает результаты.
3. В **Settings → Variables → Actions** добавьте `TELEGRAM_RELAY_URL` — URL вашего Worker, например `https://math7-telegram-relay.<ваш-subdomain>.workers.dev`. URL узнаётся после первого развёртывания; первый раз можно локально развернуть `wrangler deploy`, получить URL в выводе, сохранить его как Variable и запустить GitHub Pages workflow повторно.
4. В `wrangler.toml` проверьте `ALLOWED_ORIGIN`: это origin опубликованного Pages сайта без пути, например `https://BaikovaAlina.github.io`.
5. Выполните локально `npx wrangler login`, затем `npx wrangler deploy` из корня репозитория. Для автоматизации можно запустить workflow **Actions → Deploy Telegram relay → Run workflow** после добавления четырёх Secrets. Workflow публикует Worker и устанавливает Telegram Secrets в него.
6. В Pages откройте ⚙️ настройки, введите тот же Chat ID, который сохранён в `TELEGRAM_CHAT_ID` Worker, и нажмите «Проверить связь». Worker принимает только запросы с разрешённого Pages origin, ограничивает частоту отправки и использует фиксированного получателя.
7. Если впервые собираете и URL Worker ещё неизвестен: сначала разверните relay, добавьте URL в GitHub Variable, затем повторно запустите Pages workflow.

**Важно:** публичная веб-страница не может скрыть переданный ей секрет. Именно поэтому `config.js` сохраняет `__TELEGRAM_BOT_TOKEN__` и `__TELEGRAM_CHAT_ID__` как плейсхолдеры, а workflow Pages не заменяет их. Worker Secrets — единственное место, куда следует класть реальные токен и Chat ID.

### Перевыпуск скомпрометированного токена

Токен, который когда-либо отправляли в переписке/публичном месте, нужно считать раскрытым. В `@BotFather` отзовите старый токен (`/revoke` в управлении токеном бота) и выпустите новый. Обновите Secret `TELEGRAM_BOT_TOKEN` в GitHub, затем заново запустите **Deploy Telegram relay** — команда запишет актуальный секрет в Worker. Удаление значения из исходников не отзывает старый токен.

## Обновление банка материалов

- Редактируйте памятки `THEORY_DATA` в `theory.js` и варианты `TASKS` в `tasks.js`.
- Ключи должны соответствовать `K-1`…`K-24` и `D-1`…`D-24` в `index.html` и `trainer.html`.
- После правок выполните `node --check tasks.js`, `node --check theory.js` и самопроверку answer-key перед push.
- Тематическое планирование и задачи являются тренажёрным подбором по перечисленным разделам ФГОС/ФОП, а не утверждённой рабочей программой конкретной школы. Последовательность тем и глубина изучения могут различаться по УМК; учитель адаптирует материал к локальной рабочей программе.
